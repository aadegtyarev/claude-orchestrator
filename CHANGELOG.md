Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [SemVer](https://semver.org/lang/ru/). До 1.0 публичный контракт

## [Unreleased]

### Ломающие изменения
- **Проект переименован: `tg-claude-orchestrator` → `claude-orchestrator`.**
  Репозиторий на GitHub переименован (старый адрес редиректит), а из кода убраны
  остатки прежнего имени и совместимость с ним:
  - каталог сессий по умолчанию — `~/claude-orchestrator-sessions`
    (было `~/tg-claude-sessions`);
  - `install.sh` больше не снимает старый юнит `tg-claude-orchestrator`;
  - из состояния сессий убрана миграция формата «до мульти-адаптеров»
    (`thread_id` → `bindings`).
- **`MODULES` в `.env` больше не поддерживается**: кошелёк включается только
  `SANDBOX_BWRAP_WALLET`. Двух источников истины для одного модуля больше нет;
  оставшийся `MODULES` в `.env` даёт понятный отказ на старте, а не тихий игнор.

  **Миграция существующей установки** (порядок важен — cwd сессии зашит сразу в
  нескольких местах):
  1. `systemctl --user stop claude-orchestrator`;
  2. перенести каталог сессий: `mv ~/tg-claude-sessions ~/claude-orchestrator-sessions`
     (либо оставить старый путь, прописав его в `SESSIONS_DIR`);
  3. в `.sessions.json` заменить старый префикс в `cwd` (и в `linked_path`, если
     проект тоже переехал);
  4. перенести транскрипты Claude Code: каталог `<профиль>/projects/` именуется
     закодированным `cwd`, поэтому сессиям БЕЗ привязанного проекта нужно
     переименовать `-home-<user>-tg-claude-sessions-<имя>` в
     `-home-<user>-claude-orchestrator-sessions-<имя>` — иначе они поднимутся
     без контекста;
  5. убрать `MODULES` из `.env`;
  6. `./install.sh` (перегенерирует юнит; если каталог репозитория тоже
     переименован, сначала пересоздай `.venv` — в нём зашиты абсолютные пути) и
     `systemctl --user start claude-orchestrator`.

### Добавлено
- **У профиля появился свой адрес API** — `base_url` в
  `<профиль>/profile.toml`: `""` возвращает сессию на прямой
  `api.anthropic.com`, строка задаёт свой адрес, файла нет — поведение прежнее.
  Значение перекрывает общий `CLAUDE_ENV_ANTHROPIC_BASE_URL` и работает
  одинаково в `claude-box --profile` и в сессиях оркестратора; `claude-box
  profile` теперь показывает адрес рядом с именем профиля.

  Адрес API оказался свойством учётки, а не машины. Учётка Team берёт
  managed-настройки своей организации (`channelsEnabled`, плагины, объявления,
  policy-limits) с эндпоинта настроек прямого `api.anthropic.com`, а локальный
  прокси-релей обслуживает только `/v1/messages` — остальное 404. Настройки не
  доезжали, и Claude Code честно писал «Channels are not enabled for your org»,
  хотя в консоли организации каналы включены: сессия поднималась, `/ping` и
  `/notify` отвечали 200, а сообщения уходили в никуда. Замер 15.08.2026 на
  одних и тех же кредах Team-учётки: прямой адрес — сообщение из канала пришло
  в сессию и модель ответила; тот же запуск через прокси — баннер запрета и
  тишина. Одной общей переменной этот выбор выразить было нельзя: личной учётке
  прокси нужен, командной противопоказан.
- **Сессия больше не молчит, когда её dev-канал не загрузился.** Учётка из
  Team-орга запрещает dev-каналы: Claude Code пишет «Channels are not enabled
  for your org» и канал не поднимается. Но channel-сервер подключается обычным
  `--mcp-config`, а не гейтом каналов, поэтому он жив: `/ping` отвечает 200
  (сессия числится готовой), `POST /notify` тоже 200 — и сообщение растворяется.
  Со стороны оператора это выглядело как «сессия работает, модель думает» —
  часами. Теперь:
  - состояние канала определяется по баннеру в `claude.log` — в окне старта
    ТЕКУЩЕГО процесса (лог накопительный и переживает рестарты, а дальше в нём
    наматывается беседа) на готовности сессии и при первом сообщении, пока
    вердикта нет. Фраза матчится целиком: в логе лежит и разговор, поэтому
    цитата баннера обязана отличаться от самого баннера;
  - канал не загрузился — оператор получает заметку с причиной и способами
    починки (`/profile` с другой учёткой либо `channelsEnabled: true` в
    managed settings орга);
  - нештатный режим виден постоянно: пометка «⌨️ без канала» в списке сессий
    (Telegram и веб) и «⌨️ через терминал» в бабле каждого сообщения;
  - **сообщения всё равно доходят**: вместо push они печатаются прямо в
    терминал сессии (bracketed paste, чтобы многострочный текст остался одним
    сообщением) в том же конверте `<channel source=… context_id=…>`, что даёт
    настоящий канал — иначе модель ответила бы с чужим `context_id`;
  - конверт при этом клеим мы, а не Claude Code (у канала текст и `context_id` —
    раздельные поля JSON), поэтому текст сообщения обезврежен: `<` перед тегом
    `channel` экранируется, иначе пересланный лог с `</channel>` внутри закрыл
    бы конверт и открыл свой — с чужим `context_id`, и ответ ушёл бы не в тот
    чат. Обычные угловые скобки (код, диффы) доходят нетронутыми;
  - пара «вставка + Enter» сериализована локом: два одновременных сообщения
    (оператор дослал второе, телеграм и веб разом) иначе слиплись бы в одном
    поле ввода, а второй Enter ушёл бы по пустому.

  Обход односторонний: он несёт трафик оператор → модель. Ответы модели идут
  обычным путём, а вот запросы разрешений, которые приходят каналом, при
  заблокированном канале не придут — это фолбэк, а не замена.
- **Терминал в чате стал терминалом, а не диктовкой команд по одной.** Раньше
  каждая команда требовала префикса `/bash`, ответ на «y/n» — отдельной команды
  `/bashin`, длинный вывод обрезался, а прервать убежавшую команду можно было
  только дождавшись таймаута. Теперь:
  - `/term on` — липкий режим топика: обычные сообщения уходят в шелл, `>` перед
    сообщением отправляет его claude, `>>` экранирует сам `>` (чтобы работало
    `> out.txt`). В главном чате режим запрещён сознательно: там шелл идёт по
    хосту с правами оператора, и случайно отправленное сообщение выполнилось бы
    на нём. `/term` без аргументов показывает статус и рабочий каталог.
  - **Ответ работающей команде — обычным сообщением.** Пока команда ждёт ввода,
    текст уходит ей на вход (бот подтверждает реакцией, а не сообщением, чтобы
    диалог из пяти «y» не рождал пять ответов). `/bashin` убран из меню как
    рудимент — сама команда осталась рабочей.
  - **Правка своего сообщения переисполняет команду** и обновляет тот же ответ:
    ошибся — поправил, а в чате остался один чистый вариант вместо трёх попыток.
  - **Кнопки под выводом**: ⏹ прервать (Ctrl-C), ↻ повторить, 🕘 последние
    команды — замена «стрелке вверх», которой в чате нет.
  - **Длинный вывод приезжает файлом**, а не обрезком с хвоста; в папке сессии
    хранятся последние 20 таких файлов. Оговорка: вывод читается из буфера
    терминала (~200 КБ), поэтому совсем болтливые команды по-прежнему стоит
    перенаправлять в файл прямо в команде — это описано в `ORCHESTRATOR.md`.
- **Профиль Claude Code на сессию: `/new … --profile work`.** Профиль — отдельная
  учётка (свои токены, скиллы, транскрипты); раньше он был только у `claude-box`,
  а все сессии оркестратора делили один `CLAUDE_CONFIG_DIR`. Дефолт задаёт
  `CLAUDE_PROFILE` в `.env`, сессия переопределяет его при создании, а
  `--profile ""` — явный отказ от профиля. Выбор живёт с сессией (resume/`/clear`
  поднимают её тем же профилем) и помечен в `/list` и веб-списке. Каталоги общие
  с `claude-box`, поэтому профиль виден обоим. Под `agent-vm` профиль честно
  отвергается: гость держит креды у себя и хостовый `CLAUDE_CONFIG_DIR`
  игнорирует. Профили переехали из `box_cli/` в автономный `box/` (в `box_cli`
  остался реэкспорт) — валидация имён и симлинк-гигиена теперь одна на всех.
- **`/profile` — смена учётки на живой сессии.** Профиль можно переключить не
  только при создании: `/profile` покажет текущую учётку, `/profile <имя>`
  перезапустит Claude под другой учёткой, а `/profile ""` вернёт сессию на общую
  учётку оркестратора. Файлы сессии не трогаются — cwd (папка проекта) и
  приватный дом живут по имени сессии, а не по профилю, меняется только учётка
  (токены/скиллы/транскрипты), поэтому прежний диалог в новой учётке не
  переносится (стартует новый). Под `agent-vm` — честный отказ. Веб: `POST
  /api/sessions/{name}/profile`.
- **`MIN_FREE_RAM_MB` — сессия не стартует, если машине не останется памяти.**
  Перед подъёмом процесса оркестратор сверяет `MemAvailable` с ценой сессии
  (под `agent-vm` — её `AGENT_VM_MEMORY_GIB`, под `bwrap`/`off` — оценка
  процесса claude) и отказывает заранее, называя числа. Раньше выбор жертвы
  оставался за OOM-killer'ом, а он убивает обычно не новую сессию, а соседнюю.
  По умолчанию 1024 МБ; `0` выключает проверку. Работает и на `/new`, и на
  возобновлении остановленной сессии.
- **Редизайн claude-box: кошелёк и launcher вынесены в автономные пакеты.**
  Кошелёк секретов переехал из `orchestrator/modules/wallet` в пакет `vault/`
  (домен, демон, MITM-прокси, коннекторы, policy) — без зависимостей оркестратора;
  launcher сессий — в `box/` (PTY-запуск, авто-диалоги, готовность «по тишине»).
  Оркестраторный модуль стал тонким адаптером; поведение бота 1:1. См.
  `vault/README.md`, `box/README.md`.
- **`claude-box` — standalone-CLI** (`bin/claude-box`): запуск `claude` в
  песочнице (`--engine bwrap|off|agent-vm`/`--vm`) без оркестратора, с профилями
  (`--profile`, изолированная идентичность claude), кошельком (`--wallet`:
  прокси-секрет → MITM, host/inject → PATH-шимы) и unattended-режимом (`-p`:
  deny+log вместо вопросов). `bin/vault` — host-side CLI демона кошелька.
- **Прокси-секреты и коннекторы кошелька** (§4.5): секрет с `connector` и `scope`
  авторизуется MITM-прокси на проводе (значение в песочницу не входит). Есть
  `generic-bearer` (bearer + скоуп по URL-префиксам) и `gdocs` (Google Docs, deny
  share/export вне скоупа). Скоуп читается из `secrets.toml` живьём (по mtime):
  правка и отзыв действуют без перезапуска (`rm secrets.toml` отзывает доступ).
- **ASK-грант «разрешить навсегда»** (§4.6): запрос вне скоупа спрашивает
  оператора кнопками (в боте и вебе одинаково), третий исход «навсегда» пишет
  узкий грант в `secrets.toml`; отзыв — `/wallet scope <имя> -<url>`. В tty
  claude-box — то же `[y/N/a]`, под `-p` — deny+log.

### Исправлено
- **Профиль поверх существующей учётки ронял запуск в песочнице.** Если
  `<профиль>/.claude` сделать симлинком на уже настроенную учётку (`~/.claude`)
  — а это единственный способ выбрать её, не копируя гигабайты и не логинясь
  заново, — `claude-box --profile` падал с `bwrap: Can't bind mount … Unable to
  mount source on destination`: монтировать В назначение-симлинк bwrap не умеет.
  Теперь и в `CLAUDE_CONFIG_DIR`, и в бинд едет раскрытый путь цели
  (`box.profiles.real_config_dir`) — один путь вместо двух, иначе внутри
  песочницы переменная указывала бы в несуществующий каталог и claude молча
  завёл бы пустую учётку. Для профиля без симлинка поведение не меняется.
- **Болтливая команда в `/bash` не доезжала вовсе.** Вывод искали заново в
  кольцевом буфере терминала (200 КБ): команда, напечатавшая больше, вытесняла
  из него служебную метку начала, оркестратор терял точку отсчёта, не видел
  конца команды и досиживал до таймаута в 10 минут с пустым результатом. То
  есть «полный вывод файлом» отказывал ровно на сборках и больших прогонах
  тестов, ради которых задумывался. Теперь вывод перехватывается потоком и
  пишется в файл по мере поступления — проверено на 200 тысячах строк; в
  памяти остаётся только то, что влезает в сообщение. Файл заводится лениво,
  поэтому обычный `ls` по-прежнему ничего не оставляет на диске. Попутно:
  Telegram-адаптер больше не читает файл целиком в память ради подсчёта строк
  и честно сообщает путь, если вывод перевалил за лимит в 50 МБ.
- **`MAX_INSTANCES` считал остановленные сессии.** Лимит задумывался как
  «сколько сессий работает ОДНОВРЕМЕННО», а считал все записи подряд — включая
  закрытые вручную, уснувшие по простою и вообще все сразу после рестарта
  оркестратора (при старте записи восстанавливаются остановленными). В итоге
  `/new` упирался в лимит при нуле живых процессов, хотя ресурсов никто не
  занимал. Теперь в счёт идут только запущенные; имена по-прежнему уникальны
  среди всех записей. Лимит заодно стал проверяться на всех путях, которые
  поднимают процесс, — при возобновлении остановленной сессии и при `/clear`
  на ней: раньше через них он обходился. Слот держится всё время подъёма
  (старт claude занимает секунды), поэтому два параллельных запуска больше не
  проходят лимит оба, а перезапуск живой сессии (`/clear`, смена модели,
  авто-переподъём) не отдаёт своё место конкурентному `/new`.
- **`CLAUDE_ENV_*` молча пропадали под `SANDBOX=agent-vm`.** Мы задавали их в env
  процесса, а `claude` живёт в microVM, куда env не течёт (замерено: в госте
  `ANTHROPIC_BASE_URL=unset`). Оператор задавал свой прокси и был уверен, что
  сессия ходит через него, — она шла мимо: другой бэкенд, маршрутизация моделей
  и биллинг. Теперь переменные доставляются через блок `env` файла настроек (он
  монтируется в гостя, и его читает сам клиент), адрес на хостовом loopback
  переписывается на LAN-адрес хоста (`AGENT_VM_HOST_IP` — переопределить), а
  раннер открывает гостю egress ровно к этому адресу. Свой `base_url` без токена
  (`CLAUDE_ENV_ANTHROPIC_AUTH_TOKEN`/`_API_KEY`) теперь отказывает на старте с
  объяснением: кред-прокси agent-vm подставляет токен только своему эндпоинту,
  и без своего токена сессии падали «Execution error» без внятной причины.
- **`CLAUDE_CONFIG_DIR` под agent-vm** пробросить нельзя (хостовый путь с
  кредами) — вместо тихого игнорирования WARNING на старте с объяснением.

### Изменено
- **Готовность сессии ждём по тишине, а не по общему таймауту.** Раньше жёсткие
  60с: под `SANDBOX=agent-vm` первый запуск тянет OCI-образ **минутами**, и
  сессия падала «не поднял channel-сервер» ещё до старта Claude. Теперь дедлайн
  продлевается, пока растёт `claude.log` (признак жизни: качается образ, грузится
  VM, стартует Claude); молчание дольше 60с — отказ, сверху потолок 15 мин.
  Зависший процесс по-прежнему падает быстро, а текст ошибки говорит, что именно
  случилось (молчание или потолок), и советует прогреть образ `agent-vm setup`.
- **`/stats` под agent-vm честно говорит, что недоступен.** Транскрипт Claude
  лежит внутри microVM, а оркестратор читает его на хосте — сообщение «транскрипт
  ещё не создан» обещало то, что не наступит никогда.
- **Недоступные фичи больше не оставляют следов в интерфейсах.**
  `OrchestratorCore.features()` — единый источник правды о том, что работает при
  текущей конфигурации, и `COMMAND_FEATURE` — карта «команда → нужная фича».
  Telegram убирает такие команды из меню «/» и из `/help`, веб не рисует кнопку
  (список приходит в WS-hello). Правило: выключенное или неработающее считаем
  несуществующим — пункт меню или кнопка, ведущие к отказу, это ложное обещание.
  Новая фича под условием = одна запись в ядре, а не правки в каждом адаптере.
  Сейчас так гейтятся `/wallet` (кошелёк вне bwrap) и `/stats` (под agent-vm);
  `/bash` намеренно не гейтится — в главном чате это рабочий терминал хоста.
- **Модуль объявляет требуемую песочницу; кошелёк вне `SANDBOX=bwrap` не
  включается даже явным `MODULES=wallet`** (`Config.MODULE_REQUIRES_SANDBOX`).
  Раньше связка `MODULES=wallet` + `SANDBOX=agent-vm` была тихим no-op: демон на
  хосте поднимался, `.wallet.json` и обёртки писались в дом сессии, но в гостя не
  попадали ни они, ни env-маркеры — оператор считал секреты защищёнными, а в
  сессии кошелька не было. Теперь модуль пропускается с WARNING, объясняющим,
  что именно недоступно и что делать. Под agent-vm креды git/gh и Claude держит
  его собственный прокси (значения модели не выдаются) — типовая работа с git/gh
  не страдает; остальные секреты требуют `SANDBOX=bwrap`.

### Исправлено (ранее)
- **Текст беседы мог впечатать клавишу в stdin сессии («your message was just 2»).**
  Авто-ответчик стартовых диалогов матчил маркеры по скользящему окну вывода
  ВСЮ жизнь сессии, поэтому ответ модели со словами «yes, I accept» слал `2\r`
  в Claude как нажатие. Матчер вынесен в `_DialogAnswerer` и глушится, как
  только channel-сервер ответил на `/ping` (стартовые диалоги позади) — по
  событию, а не по таймеру: под agent-vm первая загрузка образа занимает минуты.
  Заодно отвечает на все диалоги, склеенные в один чанк вывода, а не только на
  первый. Ранее
  это списывали на CPR-зонды под agent-vm — замер показал, что winsize в гостя
  наследуется, а на CPR у нас никто не отвечает (см. docs/agent-vm-integration.md).
  Побочно: `strip_ansi` больше не гоняется на каждый чанк вывода за всю сессию.
- **Пустой `reply_to_user` молча терял ответ.** Изредка тул приходил с `text=""`
  (наблюдалось под agent-vm), и пользователь получал пустое сообщение. Теперь
  канал отклоняет пустой текст с `isError` — модель перепосылает ответ — и
  логирует сырые `arguments` для диагностики первопричины.
- **Кнопка ⏭ «висела» всегда, вотчдог зависаний не срабатывал (под bwrap).**
  Оба сигнала были завязаны на `has_children` (есть ли дочерний процесс через
  `/proc`), а под `SANDBOX=bwrap` у процесса сессии ВСЕГДА есть ребёнок
  (внутренний bwrap pid-ns init) → `has_children` структурно всегда True. Теперь
  «идёт foreground-команда» определяется по хукам Claude Code (PreToolUse без
  PostToolUse), а не по `/proc`. Вотчдог снова детектит зависания (`is_busy` —
  только CPU-дельта дерева; случай «тул идёт, но CPU замер» ловит отдельный
  in-flight сигнал). Заодно ушёл скан `/proc` на каждый flush бабла.
- **Кнопка ⏭ в Telegram больше не «прыгает» в ряду.** Раньше она то появлялась,
  то исчезала — можно было тапнуть по месту исчезнувшей и попасть в соседнюю
  (⛔ Прервать ход). Теперь она ВСЕГДА на своём месте: когда есть что свернуть —
  `⏭ Разблокировать`, когда нечего — дефис-заглушка `—`, тап по которой ничего
  не делает (молча). Иконка держится ещё несколько секунд после тула
  (grace-дебаунс), чтобы не мигать в паузах между командами. Веб и так рисовал
  кнопку неактивной на месте (`disabled`) — там ничего не менялось.
- **CI не гонял тесты кошелька.** Четыре тест-файла (`wallet_shared`,
  `wallet_inject`, `wallet_shims`, `send_retry`) не собирались pytest'ом (точки
  входа были `run`/`main`, а не `test_*`) — security-критичная логика подстановки
  секретов регрессировала бы с зелёной галкой. Точки входа переименованы, в CI
  добавлен шаг `tests/run_all.sh` (оба раннера). Суита 57→81.
- **Права `secrets.toml.tmp`.** Временный файл при правке `/wallet` писался с
  umask-правами (обычно 0644) до `chmod 0600` — узкое окно, где значения секретов
  group/other-readable. Теперь создаётся сразу 0600 (`os.open O_CREAT|O_TRUNC`).
- **Потеря сообщения при медленном хендшейке.** `send_to_claude` ретраил только
  connection-refused; при хендшейке >10 c POST падал `asyncio.TimeoutError` в
  обход `SEND_RETRY_TIMEOUT` — сообщение молча терялось. Теперь ретрай ловит и
  таймаут в окне.

### Добавлено
- Тесты security-поверхностей без покрытия: reply-сервер (401/400/500/политики),
  жизненный цикл `TurnSupervisor` (watchdog/error-relay/дедуп), гейт доступа
  Telegram (deny-all при пустом ALLOWED_USER_IDS, привязка чата), отказные ветки
  `sandbox.available()` / `AgentVmRunner.preflight()` / `proc_tree_signals`.

### Изменено
- **Backoff у статус-бабла.** При устойчивом сбое доставки во все адаптеры `_flush`
  больше не крутится каждые 1.5 c до закрытия бабла — после 5 подряд-провалов
  само-респин прекращается, доставка возобновляется на следующем реальном событии.
- Дедуп-рефакторинг без смены поведения: единый примитив редакции секретов
  (`_redact_text`), декораторы 404/401-guard (`with_session`/`_authed`), фабрика
  роутов reply-сервера, `_each_transport`-бродкаст, `_allocate_port`/`_write_configs`
  в lifecycle сессий, fail-safe парсер булевых флагов.

## [0.2.5] — 2026-07-20

- **Прозрачность фоновых процессов сессии.** Из `Stop`-хука (авторитетно от

## [0.2.4] — 2026-07-20

  при отсутствии файла кошелёк лишь предупреждал «секретов нет». Существующий

  cwd процесса-оркестратора (репозитория), а по умолчанию листался `SESSIONS_DIR`.

## [0.2.1] — 2026-07-20

### Исправлено
- **Обёртки кошелька не находились в песочнице.** `session_path` клал в PATH
  хостовый путь `.homes/<имя>/.wallet-bin`, которого внутри песочницы нет

### Добавлено
- **`SANDBOX_X11`** (по умолчанию off): X/Wayland в песочнице по умолчанию

## [0.2.0] — 2026-07-20

### Добавлено
- **Кошелёк секретов: прозрачный шлюз.** Модель зовёт `gh`/`git`/`curl`/`ssh`
  как обычно — per-session обёртки в `.wallet-bin` (первыми в PATH песочницы)
  заворачивают вызов в `wallet exec`, демон подбирает секрет по команде и
  исполняет её на хосте. Больше не нужно вручную помнить про `wallet run`.
  - `git`-обёртка особая: сетевые подкоманды (`push`/`fetch`/`pull`/`clone`/…)
    идут через кошелёк, локальные (`status`/`commit`/`diff`) — настоящим git в
    песочнице.
  - inject-токен виден модели привычной env-переменной `$NAME` (в песочнице —
    маркер, реальное значение демон подставляет на хосте; `$NAME_FILE` — для
    ключа/сертификата файлом).
  - `SessionManager.path_hooks` — модули добавляют каталоги в начало PATH
    песочницы.
  - CLI: новая команда `wallet exec <cmd>` (подбор секрета по команде).

### Изменено
- Системный промпт и справка кошелька переписаны: ведут с «зови инструмент как
  обычно», `wallet run` — ручной fallback.
- Документация `docs/secrets-wallet.md` переписана с нуля под прозрачную модель;
  README и `.env.example` актуализированы.

### Удалено
- Плейсхолдеры `{{secret}}`/`{{secret_file}}` — заменены на env-переменные
  `$NAME`/`$NAME_FILE`.
- Поле секрета `inject_at_start` (shared-секрет с `env` теперь всегда попадает в
  env сессии реальным значением).
