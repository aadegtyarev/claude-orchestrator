# claude-orchestrator

Несколько параллельных сессий [Claude Code](https://code.claude.com/docs) —
из Telegram и из браузера. Каждая сессия живёт в своей папке проекта, помнит
контекст, переживает перезапуск и работает в песочнице.

Поставил на своей машине (или на домашнем сервере) — и дальше пишешь Claude из
телефона, как обычному человеку в мессенджере: «почини тесты в бэкенде», «сделай
ревью PR», «подними стенд». Видно, что модель делает прямо сейчас; можно
прервать, спросить отчёт, ответить на запрос разрешения — не подходя к
компьютеру.

```
⏳ Работаю… · sonnet-5
📨 почини падающие тесты
⚡ Bash: pytest -x
  ↳ 5× 📖 Read: conftest.py
💬 Нашёл причину, чиню conftest.py
✻ Cogitating                   ← модель думает: событий нет, но она жива
[📋 Отчёт] [⏭ Разблокировать] [⛔ Прервать ход]
```

## Что это даёт

- **Много проектов одновременно.** Сессия = отдельный экземпляр Claude Code со
  своим контекстом и своей папкой. В Telegram каждая сессия — свой топик, в вебе
  — своя вкладка чата.
- **Видно, что происходит.** Живой статус: вызовы инструментов, сабагенты,
  промежуточные ответы, обращения к секретам. Не «модель что-то делает пять
  минут», а построчно.
- **Управление ходом.** Отчёт о статусе, разблокировка ввода, настоящее
  прерывание (Esc в терминал) — из чата.
- **Запросы разрешений приходят кнопками** ✅/❌ в любой интерфейс; отвечает
  первый, кто нажал.
- **Песочница.** По умолчанию каждая сессия заперта в mount-namespace: видит
  только свою папку проекта, не видит `~/.ssh`, чужие проекты и твой домашний
  каталог. Для отдельной сессии изоляцию можно ослабить или усилить.
- **Кошелёк секретов.** `git push`, `gh`, `curl` с токеном работают в сессии,
  но самих значений модель не видит — они подставляются на хосте.
- **Файлы в обе стороны.** Пришли фото/документ — Claude получит путь; он
  пришлёт результат обратно.

Проект решает не ту задачу, что официальный Telegram-плагин Claude Code
(`/plugin install telegram@claude-plugins-official`): тот — мост «один чат ↔
одна сессия». Здесь — много именованных сессий, привязка к папкам, статус-баблы,
resume, песочница, несколько интерфейсов сразу.

## Требования

- Linux, Python ≥ 3.10 (в WSL2 работает; macOS не поддерживается — нет
  bubblewrap и пользовательского systemd)
- [Claude Code](https://code.claude.com/docs) ≥ 2.1 в `PATH`, **залогиненный**
  (channels требуют подписки claude.ai или Console)
- `bubblewrap` — песочница по умолчанию: `sudo apt install bubblewrap`
  (можно и без неё, см. [`docs/CONFIG.md`](docs/CONFIG.md))
- для Telegram: бот от [@BotFather](https://t.me/BotFather) и группа с топиками,
  где бот — админ с правом «Manage Topics»
- для веба ничего не нужно — он локальный

Сессии работают через **channels** — механизм Claude Code, которым внешняя
программа общается с запущенным клиентом. Расход идёт по той же подписке, под
которой залогинен `claude` на этой машине: несколько сессий тратят общую квоту
(`/usage` показывает остаток).

⚠️ Channels — research preview: флаги и протокол могут меняться между версиями
Claude Code.

## Быстрый старт

```bash
git clone https://github.com/aadegtyarev/claude-orchestrator.git
cd claude-orchestrator
./install.sh                 # venv, зависимости, systemd user-юнит; создаст .env из примера
nano .env                    # минимум: TELEGRAM_BOT_TOKEN и ALLOWED_USER_IDS
systemctl --user enable --now claude-orchestrator
journalctl --user -u claude-orchestrator -f     # смотрим, что поднялось
```

Минимальный `.env` для Telegram:

```ini
TELEGRAM_BOT_TOKEN=123456:AA...        # от @BotFather
ALLOWED_USER_IDS=123456789             # твой Telegram ID; пусто = бот молчит всем
```

Несколько человек — через запятую; все они пользуются одними и теми же сессиями
в общей группе.

Только браузер, без Telegram:

```ini
ADAPTERS=web
```

URL с токеном печатается в лог при старте (как у Jupyter).

Дальше в Telegram: добавь бота в группу с включёнными топиками, дай права
админа, отправь `/chat_id` — бот запомнит группу. Потом `/new мой-проект
/home/user/projects/api` — и пиши в появившийся топик.

Пошагово, с картиной «что где нажимать» и разбором типовых ошибок —
[руководство пользователя](docs/GUIDE.md).

## Безопасность в двух словах

Доступ строго по белому списку: пустой `ALLOWED_USER_IDS` — бот игнорирует все
сообщения. Кто в списке, тот и одобряет запросы разрешений. Веб защищён токеном
и слушает `127.0.0.1`; наружу выставляй только за reverse-proxy с TLS. Сессия по
умолчанию в песочнице, но `/bash` в главном чате — это твой хост целиком, без
изоляции (команда только для тебя, не для модели).

Подробности и модель угроз — в [руководстве](docs/GUIDE.md#изоляция-и-песочница)
и [`docs/secrets-wallet.md`](docs/secrets-wallet.md).
