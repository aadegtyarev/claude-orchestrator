# claude-orchestrator

Три слоя вокруг [Claude Code](https://code.claude.com/docs), каждый работает
сам по себе:

| Слой | Что это | Кому |
|------|---------|------|
| **`claude-box`** | запустить `claude` в песочнице: своя изоляция, отдельная учётка, секреты без выдачи значений | человеку за терминалом и CI |
| **`vault`** | кошелёк секретов: `git push`, `gh`, `curl` с токеном работают, а значения модели не видны | тому, кто не хочет класть боевой токен в окружение агента |
| **оркестратор** | много именованных сессий с интерфейсом в Telegram и браузере | тому, кто ведёт несколько проектов и управляет ими с телефона |

Нижний слой — базовый: оркестратор поднимает такие же изолированные сессии,
просто много и с чатом поверх. Взять можно только его.

## Начать снизу: одна изолированная сессия

```bash
git clone https://github.com/aadegtyarev/claude-orchestrator.git
cd claude-orchestrator
sudo apt install bubblewrap           # песочница
bin/claude-box                        # claude в песочнице, терминал твой
```

Процесс видит рабочий каталог и свой временный дом — и больше ничего: ни
`~/.ssh`, ни соседних проектов, ни настоящего `$HOME`. Дальше:

```bash
bin/claude-box init work              # отдельная учётка claude (свой профиль)
bin/claude-box --profile work         # запуск под ней
bin/claude-box --wallet gh            # дать доступ к gh, не показывая токен
bin/claude-box -p "почини тесты"      # без интерактива, для CI
```

Подробно — [руководство по `claude-box`](docs/BOX.md).

## Дальше: секреты

Кошелёк держит значения на хосте и отдаёт модели результат, а не сам секрет.
`git push` и `gh pr create` работают как обычно, `curl` получает заголовок с
токеном — но `echo $TOKEN` в сессии покажет лишь маркер.

```bash
bin/vault serve                       # демон кошелька
bin/claude-box --wallet deploy-key    # сессия с этим секретом
```

Подробно — [кошелёк секретов](docs/WALLET.md).

## Сверху: много сессий и чат

Оркестратор поднимает такие же сессии, но по одной на проект, и даёт к ним
интерфейс: Telegram (топик на сессию) и локальный веб. Видно, что модель делает
прямо сейчас; можно прервать, спросить отчёт, ответить на запрос разрешения — с
телефона.

```
⏳ Работаю… · sonnet-5
📨 почини падающие тесты
⚡ Bash: pytest -x
  ↳ 5× 📖 Read: conftest.py
💬 Нашёл причину, чиню conftest.py
✻ Cogitating                   ← модель думает: событий нет, но она жива
[📋 Отчёт] [⏭ Разблокировать] [⛔ Прервать ход]
```

```bash
./install.sh                          # venv, зависимости, systemd-юнит, .env
nano .env                             # TELEGRAM_BOT_TOKEN, ALLOWED_USER_IDS
systemctl --user enable --now claude-orchestrator
```

Подробно — [руководство по оркестратору](docs/ORCHESTRATOR.md) и
[справочник настроек](docs/CONFIG.md).

Задача у проекта не та, что у официального Telegram-плагина Claude Code
(`/plugin install telegram@claude-plugins-official`): тот — мост «один чат ↔
одна сессия». Здесь — много именованных сессий, привязка к папкам проектов,
статус-баблы, продолжение после перезапуска, песочница, несколько интерфейсов
сразу.

## Требования

- Linux, Python ≥ 3.10 (в WSL2 работает; macOS не поддерживается — нет
  bubblewrap и пользовательского systemd)
- [Claude Code](https://code.claude.com/docs) ≥ 2.1 в `PATH`, **залогиненный**
- `bubblewrap` для песочницы: `sudo apt install bubblewrap`
- `claude-box` и `bin/wallet` обходятся системным Python, без зависимостей
- оркестратору дополнительно нужны пакеты из `requirements.txt` (ставит
  `install.sh`), бот от [@BotFather](https://t.me/BotFather) и группа с топиками

Сессии работают через **channels** — механизм Claude Code, которым внешняя
программа общается с запущенным клиентом. Расход идёт по той подписке, под
которой залогинен `claude` на этой машине.

⚠️ Channels — research preview: флаги и протокол могут меняться между версиями
Claude Code.

## Безопасность в двух словах

Сессия по умолчанию в песочнице: видит рабочий каталог и свой дом, не видит
`~/.ssh`, чужие проекты и настоящий `$HOME`. Секреты живут на хосте — в
песочницу попадает результат их применения, а не значение.

У оркестратора доступ строго по белому списку: пустой `ALLOWED_USER_IDS` — бот
игнорирует все сообщения. Веб защищён токеном и слушает `127.0.0.1`; наружу
выставляй только за reverse-proxy с TLS. `/bash` в главном чате — твой хост
целиком, без изоляции (команда оператора, не модели).
