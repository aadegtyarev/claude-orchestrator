# `claude-box` — Claude Code в песочнице

Базовый слой проекта: одна изолированная сессия `claude`, запущенная из
терминала или из скрипта. Оркестратор ([`ORCHESTRATOR.md`](ORCHESTRATOR.md))
поднимает такие же сессии, только много и с чатом поверх, — так что всё,
описанное здесь, действует и там.

## Зачем

Claude Code запускается с правами того, кто его позвал: видит весь дом, ключи,
чужие проекты, переменные окружения с токенами. Пока задачи мелкие и знакомые,
это терпимо; на чужом репозитории, длинной автономной задаче или в CI — уже нет.

`claude-box` даёт три вещи по отдельности или вместе:

- **изоляция** — процесс заперт в свой каталог, дом и ключи хоста ему не видны;
- **отдельная учётка** — сессия работает под своим профилем claude, а не под
  твоим личным логином;
- **секреты без выдачи значений** — `git push`, `gh`, `curl` с токеном работают,
  но само значение в песочницу не попадает.

## Установка

```bash
git clone https://github.com/aadegtyarev/claude-orchestrator.git
cd claude-orchestrator
sudo apt install bubblewrap
mkdir -p ~/.local/bin
ln -sfn "$PWD/bin/claude-box" ~/.local/bin/claude-box
ln -sfn "$PWD/bin/vault" ~/.local/bin/vault      # понадобится для секретов
```

Больше ничего не нужно: `claude-box` работает на системном Python (≥ 3.10) без
зависимостей проекта. Проверка:

```bash
claude-box --help
```

`команда не найдена` — значит `~/.local/bin` не в `PATH`; добавь в `~/.profile`:
`export PATH="$HOME/.local/bin:$PATH"` и открой терминал заново.

Ставишь оркестратор — эти симлинки создаёт `install.sh`, отдельно делать ничего
не нужно.

Нужен установленный и залогиненный `claude` — проверь, что он открывается сам:
`claude`. Другой бинарь задаётся переменной `CLAUDE_BIN`.

## Первый запуск

```bash
cd ~/projects/api
claude-box
```

Откроется обычный интерактивный Claude Code — просто внутри песочницы. Терминал
твой: ввод, вывод, `Ctrl+C`, изменение размера окна работают как всегда.

Аргументы после `--` уходят самому claude:

```bash
claude-box -- --model opus
```

## Что видно из песочницы

По умолчанию (движок `bwrap`) процесс заперт в mount-namespace через
[bubblewrap](https://github.com/containers/bubblewrap), без root. Изнутри видно
**только**:

| Что | Доступ | Зачем |
|-----|--------|-------|
| рабочий каталог (откуда запущен) | чтение/запись | собственно работа |
| дом сессии | как `$HOME` | кэши и venv, которые ставит агент |
| профиль Claude Code | чтение/запись | токены, скиллы, транскрипты |
| бинарь claude и репозиторий проекта | чтение | запуск, CLI кошелька |
| системный рантайм (`/usr`, `/etc`, DNS) | чтение | библиотеки, TLS, резолвинг |

Всё остальное — другие проекты, `~/.ssh`, `~/.aws`, настоящий `$HOME` — не видно
ни на чтение, ни на запись. В отличие от встроенного `/sandbox` Claude Code (он
накрывает только Bash), обёртка накрывает все инструменты разом.

Сеть общая с хостом — она нужна для API. Графика (X/Wayland) отрезана, чтобы
процесс не мог дёрнуть GUI хоста: askpass-диалоги, скриншоты, перехват ввода.

⚠️ Раз настоящий дом скрыт, глобальный `~/.venv` и инструменты из твоего дома
агенту не видны. Окружение держи **в проекте** — рабочий каталог доступен на
запись.

## Умолчания: файл настроек

Чтобы не повторять флаги на каждом запуске, опиши, что значит «просто
`claude-box`» на этой машине:

```toml
# ~/.config/claude-box/config.toml
engine = "bwrap"     # bwrap | off | agent-vm
profile = "work"     # запускать под этим профилем; "" — без профиля
wallet = true        # включить кошелёк, когда изоляция есть
secrets = "~/.config/claude-orchestrator/secrets.toml"
```

Создавать и править файл руками не нужно:

```bash
claude-box config                  # мастер: движок, кошелёк, профиль
claude-box config show             # что сейчас задано и где лежит файл
claude-box config engine=off       # точечно, без вопросов
claude-box config profile=         # пустое значение убирает ключ
```

Мастер спрашивает то же, что `install.sh` при установке оркестратора, но
доступен всегда — перенастроить можно в любой момент, не удаляя файл. Каталог
создаётся сам. Без терминала (CI, пайп) `claude-box config` просто печатает
текущее состояние, а менять умолчания там удобнее формой `ключ=значение`.

Путь переопределяется переменной `CLAUDE_BOX_CONFIG`; файла может не быть вовсе
— тогда поведение как раньше.

**Флаг всегда сильнее файла.** `--engine off` перебивает `engine`, `--wallet gh`
— `wallet`. Чтобы разово запуститься без профиля, передай пустое значение:
`claude-box --profile ""`.

**`wallet = true` работает только там, где есть изоляция.** Под `engine = "off"`
кошелёк из файла не поднимается, и запуск об этом говорит: без песочницы он не
страхует — процесс идёт с твоими правами и читает `secrets.toml` напрямую.
(Явный `--wallet` с `--engine off` при этом остаётся рабочим: это осознанный
выбор — дать модели аутентифицированный канал, не изолируя её.)

**Опечатка не проходит молча.** Неизвестный ключ, неверный тип или битый TOML —
отказ с объяснением, а не тихий откат к умолчанию: иначе `engien = "off"`
запускал бы сессию не в той изоляции, чем ты думаешь.

## Движки изоляции

```bash
claude-box --engine bwrap     # по умолчанию: файловая песочница
claude-box --engine off       # без изоляции: полный доступ к хосту
claude-box --vm               # microVM (agent-vm), нужен KVM
```

`off` — для машин без bubblewrap и для задач, которым нужен весь хост; это
осознанный отказ от защиты, а не «облегчённый режим».

`--vm` (то же самое, что `--engine agent-vm`) поднимает сессию в микровиртуалке
через [agent-vm](https://github.com/wirenboard/agent-vm): изолируется уже ядро
ОС, а не только файловая система. Ресурсы задаются переменными `AGENT_VM_*`
(см. ниже).

### Установка microVM

Нужен **наш форк** agent-vm: в него добавлены флаги `--env`, `--egress-proxy` и
`--egress-ca`, без которых кошелёк не может провести секрет в гостя (апстрим их
не знает — запуск честно откажет на preflight). Собранный бандл лежит в релизах,
собирать локально не нужно:

```bash
mkdir -p ~/.local/share/agent-vm && cd ~/.local/share/agent-vm
gh release download --repo aadegtyarev/agent-vm \
    --pattern 'agent-vm-linux-x64-*.tar.gz'
tar xzf agent-vm-linux-x64-*.tar.gz
ln -sfn "$PWD/agent-vm-linux-x64/bin/agent-vm" ~/.local/bin/agent-vm
agent-vm --version
```

Дальше проверь, что доступен KVM: файл `/dev/kvm` существует и ты в группе
`kvm` (`ls -l /dev/kvm`, при необходимости `sudo usermod -aG kvm $USER` и
перелогиниться). Первый запуск VM тянет образ гостя — это минуты, поэтому
прогрей заранее:

```bash
agent-vm setup
claude-box --vm
```

## Профили — отдельные учётки claude

Профиль — самостоятельная идентичность Claude Code: свой каталог конфигурации
(токены, скиллы, транскрипты) и, под `bwrap`, свой `$HOME`. Личный `~/.claude`
и `~/.ssh` для такой сессии не существуют.

```bash
claude-box init work            # создать профиль (идемпотентно), напечатать путь
claude-box --profile work       # запустить под ним
claude-box profile              # список профилей
claude-box profile rm work      # удалить
```

Профили живут в `${CLAUDE_BOX_HOME:-~/.local/share/claude-box}/profiles/<имя>`.
Первый запуск под новым профилем попросит залогиниться — это ожидаемо, учётка
новая.

Из окружения такой сессии вырезаются значения, похожие на креды (`*TOKEN`,
`*SECRET`, `*KEY`, `*PASSWORD`, `*CREDENTIAL`, `SSH_AUTH_SOCK`) — иначе
«изолированная» сессия унаследовала бы твой токен из шелла. Остальное окружение
наследуется; рабочий каталог и установка claude остаются видны.

## Секреты

Секрет описывается в `secrets.toml` и выдаётся сессии по имени:

```bash
claude-box --wallet                          # все секреты, что разрешает policy
claude-box --wallet gh                       # только этот секрет
claude-box --wallet deploy --secrets ./s.toml # свой файл политики
```

Без имени работает так же, как кошелёк в оркестраторе: набор определяет
политика (`sessions` у записи секрета), а не перечисление в командной строке.
Прокси-секреты в такой набор не входят — перехват TLS поднимается под один
секрет, поэтому его нужно назвать явно; запуск об этом скажет.

Что происходит, зависит от типа секрета:

- **хостовые креды и свой токен** — в `PATH` сессии первыми встают обёртки
  `git`, `gh`, `curl`, `ssh`; вызов уходит на хост, там подставляется значение,
  обратно возвращается результат. В песочнице значения нет;
- **прокси-секрет** (для HTTPS-сервиса) — поднимается локальный перехват TLS, и
  токен подставляется на проводе; модель шлёт обычный запрос.

Режимы, формат `secrets.toml`, политика по командам и модель угроз —
[`WALLET.md`](WALLET.md). Демон кошелька для standalone-работы поднимается
командой `bin/vault serve`.

## Запуск без человека (CI)

```bash
claude-box -p "прогони тесты и почини падающие"
```

`-p` и его длинная форма `--print` — флаги самого claude; `claude-box` их узнаёт,
чтобы не поднимать интерактивную обвязку зря.

Задача выполняется без интерактива, код возврата claude становится кодом
возврата `claude-box`. Спрашивать в этом режиме некого, поэтому вопросы кошелька
(подтверждение, запрос доступа вне скоупа) не задаются, а **сразу отклоняются**
с записью в лог: модель получает внятный отказ вместо зависания. Нужны такие
секреты — разреши их в политике заранее.

Сочетается с `--vm` и `--profile`.

⚠️ Пайп в stdin (`cat data | claude-box -p …`) до claude **не доходит**: процесс
всегда под PTY, и stdin для него выглядит терминалом. Передавай данные в самом
промпте или файлом в рабочем каталоге.

## Переменные окружения

Все необязательные.

| Переменная | По умолчанию | Что делает |
|------------|--------------|------------|
| `CLAUDE_BIN` | `claude` | какой бинарь запускать |
| `CLAUDE_BOX_HOME` | `~/.local/share/claude-box` | где лежат профили |
| `CLAUDE_BOX_CONFIG` | `~/.config/claude-box/config.toml` | файл умолчаний |
| `AGENT_VM_MEMORY_GIB` | — | память microVM, целое число гигабайт |
| `AGENT_VM_CPUS` | — | число vCPU microVM |
| `AGENT_VM_IMAGE` | — | пин образа гостя |
| `AGENT_VM_HOST_IP` | авто | адрес хоста «глазами гостя» (VPN, несколько интерфейсов) |
| `AGENT_VM_EGRESS_PROXY` | — | весь исходящий трафик гостя — на указанный прокси |
| `AGENT_VM_EGRESS_CA` | — | PEM-файл CA для upstream-плеча egress-прокси |

Имена `AGENT_VM_*` те же, что у оркестратора, — значения общие для обоих слоёв.

## Границы

Проговорены явно, чтобы флаг не делал вид, что применён: сочетания ниже
завершаются кодом 2 с объяснением, а не тихо игнорируются.

| Не работает | Почему |
|-------------|--------|
| `--profile` вместе с `--vm` | внутри VM свой claude со своим профилем; хостовый каталог конфигурации туда не пробросить — agent-vm держит креды у себя |
| `--wallet` с хостовым/инъекционным секретом вместе с `--vm` | окружение в гостя не течёт, `git`/`gh` ведёт сам agent-vm, обёрткам не за что зацепиться |
| `connect` | коннекторы кошелька ждут живого OAuth-флоу — следующий трек |

`--wallet` с **прокси-секретом** под `--vm` работает: кошелёк поднимает прокси на
адресе хоста и направляет туда egress гостя, значение секрета в VM не попадает.

Ещё две границы, о которых стоит знать: рабочий каталог и сама установка claude
из песочницы видны всегда (иначе нечего запускать и не над чем работать), а под
`--engine off` изоляции нет вовсе — там кошелёк бессмыслен, потому что модель
читает креды хоста напрямую.
