## Что нужно перед началом

Помимо общих требований (Linux, Python ≥ 3.10, залогиненный Claude Code,
bubblewrap — см. [README](../README.md#требования)):

1. **Машина, которая всегда включена** — домашний сервер, мини-ПК, рабочий
   компьютер. Claude Code работает на ней, а Telegram и браузер — окна в неё.
2. **Бот и группа с топиками**, если нужен Telegram (ниже по шагам). Только веб
   — достаточно `ADAPTERS=web`.

## Установка

```bash
git clone https://github.com/aadegtyarev/claude-orchestrator.git
cd claude-orchestrator
./install.sh
```

`install.sh` создаёт виртуальное окружение, ставит зависимости, копирует
`.env.example` в `.env`, кладёт `claude-box`, `vault` и `wallet` в
`~/.local/bin`, регистрирует systemd-юнит пользователя `claude-orchestrator` и
включает linger (сервис живёт после разлогина). Скрипт идемпотентный —
запускать повторно безопасно.

Затем заполни `.env` (минимум — токен бота и свой Telegram ID, см. ниже) и
запусти:

```bash
systemctl --user enable --now claude-orchestrator
journalctl --user -u claude-orchestrator -f
```

`enable --now` означает «запустить сейчас и поднимать впредь». Впредь — это в
том числе **после перезагрузки и без входа в систему**: `install.sh` включает
для пользователя linger, поэтому его systemd-менеджер стартует вместе с машиной
и не гасится при разлогине. Проверить:

```bash
loginctl show-user "$USER" --property=Linger    # ожидаем Linger=yes
```

`Linger=no` — сервис будет жить только пока ты залогинен; включается командой
`sudo loginctl enable-linger $USER`.

В логе при старте видно, какие адаптеры поднялись, какая песочница выбрана и
включён ли кошелёк секретов.

Без systemd можно запускать вручную:
`.venv/bin/python -m orchestrator`.

## Подключаем Telegram

1. **Заведи бота.** Напиши [@BotFather](https://t.me/BotFather) → `/newbot` →
   имя и username → получишь токен вида `123456:AA...`. Его — в `.env`:

   ```ini
   TELEGRAM_BOT_TOKEN=123456:AA...
   ```

2. **Узнай свой Telegram ID** (например, у [@userinfobot](https://t.me/userinfobot))
   и впиши в белый список. Это обязательный шаг: с пустым списком бот
   игнорирует вообще все сообщения.

   ```ini
   ALLOWED_USER_IDS=123456789
   ```

   Можно перечислить нескольких через запятую — все они смогут писать сессиям и
   отвечать на запросы разрешений.

3. **Создай группу и включи в ней топики.** В Telegram: создать группу →
   настройки группы → «Темы» (Topics) → включить.

4. **Добавь бота в группу администратором** с правом «Управление темами»
   (Manage Topics) — без него бот не сможет создавать топики под сессии.

5. **Привяжи группу.** Отправь в неё `/chat_id`. Бот ответит ID группы и
   запомнит её. Можно зафиксировать явно:

   ```ini
   TELEGRAM_CHAT_ID=-1001234567890
   ```

6. Перезапусти сервис, если правил `.env`:
   `systemctl --user restart claude-orchestrator`.

Не нужен Telegram? Оставь только веб: `ADAPTERS=web`. Оба интерфейса
одновременно — `ADAPTERS=telegram,web`.

## Как всё устроено

Оркестратор разговаривает с Claude Code через **channels** — механизм самого
клиента, позволяющий внешней программе слать ему сообщения и получать ответы.
Поэтому и нужен залогиненный `claude` на машине: модель работает от твоей
подписки, а несколько сессий тратят общую квоту (остаток — `/usage`).

**Топик** — ветка внутри группы Telegram (функция «Темы»). Оркестратор заводит
по топику на сессию, чтобы разговоры разных проектов не смешивались.

**Сессия** — отдельный процесс Claude Code со своим контекстом, своей рабочей
папкой и своей историей. Сессия принадлежит оркестратору, а не Telegram:
одну и ту же сессию видно и в топике, и в браузере, ответы приходят в оба места.

**Папка проекта** (необязательная) — то, с чем модель работает. Claude
запускается прямо в ней, поэтому подхватывает `CLAUDE.md`, `.claude/` и прочие
настройки проекта, как если бы ты запустил его руками.

⚠️ Привязка папки означает **доверие** к её настройкам: project-хуки из
`.claude/settings.json` исполнятся. Авто-старт MCP-серверов проекта отключён, но
хуки грузятся через доверие. Оркестратор предупреждает в логе, если в папке есть
такие настройки. Линкуй репозитории, которым доверяешь.

**Жизненный цикл:**

```
/new ──> работает ──/close_session──> остановлена ──любое сообщение──> продолжение
                    (или падение,     (топик и история живы)  │
                     или перезапуск                           ├─ контекст продолжен
                     оркестратора)                            └─ не вышло → чистый старт, честно сообщается
```

Сессия останавливается сама после `IDLE_TIMEOUT_H` часов простоя (по умолчанию 6;
`0` — никогда; проверка идёт раз в десять минут). Запись при этом сохраняется —
достаточно написать в топик.

Продолжение — это не новый разговор: оркестратор просит Claude Code поднять
прежний диалог со всей перепиской. Если не вышло (транскрипт потерян, клиент
обновился), сессия честно скажет, что стартовала с чистого листа.

Одновременно ЗАПУЩЕНО не больше `MAX_INSTANCES` сессий (по умолчанию 5).
Остановленные слот не занимают — ни закрытые вручную, ни уснувшие по простою,
ни все разом сразу после рестарта оркестратора: процесса нет, значит и ресурсов
нет. Упёрся в лимит — останови ненужную (`/close_session`, запись и топик
сохранятся) или подними значение в `.env`.

Кроме штук, оркестратор смотрит и на саму машину: если после старта свободной
памяти останется меньше `MIN_FREE_RAM_MB` (по умолчанию 1024), сессия не
запустится и скажет, сколько памяти есть и сколько ей нужно. Это дешевле, чем
дать OOM-killer'у выбрать жертву самому — он обычно убивает не новую сессию, а
соседнюю. Проверка одинаково работает и на `/new`, и на возобновлении
остановленной сессии.

## Первая сессия

В **основном** чате группы (не в топике):

```
/new мой-проект /home/user/projects/api
```

Появится топик «мой-проект». Пиши в него как обычному собеседнику:

```
посмотри, почему падает тест test_login, и почини
```

Пока Claude работает, в топике живёт **статус-бабл** — обновляемое сообщение с
тем, что происходит. Когда ход закончится, придёт обычное сообщение с ответом.

Другие формы `/new`:

| Команда | Что делает |
|---------|------------|
| `/new бэкенд` | сессия без привязки к проекту; рабочая папка — своя папка сессии |
| `/new /home/user/api` | имя возьмётся из имени папки |
| `/new бэкенд /home/user/api` | своё имя + папка проекта |
| `/new тесты --box off` | сессия без песочницы (см. [Изоляция](#изоляция-и-песочница)) |

Имя может быть с пробелами и эмодзи — для внутренних нужд оно превращается в
slug (`[A-Za-z0-9_-]`).

## Как этим пользуются

Несколько сценариев, ради которых всё это и делалось.

**Несколько проектов сразу.** По сессии на репозиторий: `/new бэкенд
/srv/api`, `/new фронт /srv/web`. Контексты не смешиваются, каждая помнит своё,
переключение — это просто другой топик.

**Длинная задача, пока ты не за компьютером.** Поставил задачу с телефона,
закрыл чат. Модель работает; в статус-бабле видно, на каком она шаге. Спросил
📋 Отчёт — получил сводку, не прерывая работу. Ушло не туда — ⛔ Прервать.

**Работа с гитом без выдачи токенов.** Модель делает `git push` и `gh pr
create` как обычно, но значения токенов ей недоступны — их подставляет кошелёк
на хосте. В бабле видно каждое такое обращение.

**Разовая задача на самом хосте.** `/new админка --box off` — сессия без
песочницы, с доступом ко всей машине: разобрать логи systemd, починить сервис.
Осознанный режим — обычные сессии остаются изолированными.

**Быстро посмотреть самому.** `/bash` в топике — терминал в песочнице сессии,
`/bash` в главном чате — терминал на хосте. Контекст модели при этом не тратится.

**Дать модели файл.** Скинул скриншот ошибки или лог в топик — Claude получит
путь к файлу и посмотрит сам.

## Команды

### В основном чате

| Команда | Что делает |
|---------|------------|
| `/new <имя> [путь] [--box …] [--profile …]` | создать сессию (движок изоляции и учётка Claude — свои у сессии) |
| `/list` | сессии со статусами и кнопками |
| `/ls [путь]` | показать файлы на хосте |
| `/bash <команда>` | терминал **на хосте**, без песочницы |
| `/wallet` | политика кошелька секретов: просмотр и правка |
| `/skills` | список доступных скиллов Claude Code |
| `/orchestrator_web` | ссылка на веб-интерфейс с токеном |
| `/orchestrator_restart` | перезапустить оркестратор (деплой без терминала) |
| `/chat_id` | ID чата и статус привязки (работает и до настройки белого списка) |
| `/help`, `/start` | краткая справка |

### В топике сессии

| Команда | Что делает |
|---------|------------|
| текст, фото, файл | отправить Claude (остановленная сессия оживёт сама) |
| `/stats` | контекст, статистика, модель, пермиссии |
| `/perms [auto\|lock]` | авто-одобрение запросов разрешений сессии: `auto` — разрешать всё молча, `lock` — снова спрашивать |
| `/usage`, `/cost` | расходы и лимиты плана |
| `/model [имя]` | сменить модель: `opus`, `sonnet`, `haiku`, `fable` или точное имя |
| `/compact` | сжать контекст |
| `/clear` | очистить контекст (топик и сессия остаются) |
| `/bg` | фоновые процессы и кроны, которые модель оставила крутиться |
| `/bash <команда>`, `/bashin <ввод>` | терминал **в песочнице этой сессии** |
| `/term [on|off]` | липкий режим: обычные сообщения → шелл, `>` → claude |
| `/log` | скачать полный лог сессии (для отладки) |
| `/close_session`, `/stop` | остановить процесс, сохранив запись |
| `/delete_session` | удалить сессию вместе с топиком |
| другие `/команды` | уходят прямо в терминал Claude Code |

Команды, которые в текущей конфигурации не работают, не показываются вовсе — ни
в меню, ни в `/help`. Так, `/wallet` появляется только при включённом кошельке, а
`/stats` исчезает под `SANDBOX=agent-vm`: транскрипт сессии лежит внутри microVM
и на хосте его не прочитать.

## Статус-бабл и управление ходом

Пока идёт ход, в топике (и в вебе) живёт одно обновляемое сообщение:

```
⏳ Работаю… · glm-5.2          ← реальная модель (после подмены прокси)
📨 почини тесты
⚡ Bash: pytest -x
  ↳ 5× 📖 Read: conftest.py     ← инструменты сабагента, схлопнуто
💬 Нашёл причину, чиню conftest.py
✻ Cogitating                   ← живой пульс: модель думает
🕐 09:45:06
[📋 Отчёт] [⏭ Разблокировать] [⛔ Прервать ход]
```

- Серии одинаковых вызовов схлопываются (`5×`), сабагенты идут с отступом, а по
  завершении подписываются именем (`✅ Сабагент dev-planner завершил`).
- Текущая bash-команда показывается целиком, по завершении сворачивается в
  строку с итогом (`✓ · 4с`).
- «Живой пульс» (`Cogitating…`) означает, что модель работает, просто сейчас нет
  событий инструментов.
- Активность **между** ходами (например, модель поллит CI) идёт отдельным
  фоновым баблом 🌙 и сама закрывается по тишине.
- Упёршийся лимит плана распознаётся и объясняется с датой сброса — это не
  зависание.

Кнопки:

| Кнопка | Что делает |
|--------|------------|
| 📋 **Отчёт** | просит модель рассказать, что сделано/делается/осталось, и **продолжать**. Не прерывает ход |
| ⏭ **Разблокировать** | освобождает ввод, не убивая ход: долгая команда уходит в фон (Ctrl+B), ожидание фоновой задачи прерывается (Esc) |
| ⛔ **Прервать ход** | настоящий Esc в терминал: ход обрывается сразу, контекст сессии сохраняется |

Если ход закончился текстом без ответа в чат, страховочный хук всё равно
доставит финал — «потерянных» ответов быть не должно.

`SHOW_TOOL_CALLS=false` убирает строки инструментов; `DELETE_BUBBLE=false`
оставляет бабл после ответа как журнал.

## Запросы разрешений

Режим задаётся `PERMISSION_MODE` (по умолчанию `auto`). Во всех режимах, кроме
`bypass`, Claude спрашивает разрешение на рискованные действия — запрос приходит
кнопками ✅/❌ во все интерфейсы сразу. Побеждает первый ответ; локальный
TUI-диалог на хосте продолжает работать параллельно.

- `auto` — судья Claude Code решает сам, спрашивает на рискованном;
- `bypass` — не спрашивать ничего (`--dangerously-skip-permissions`);
- `acceptEdits`, `manual`, `dontAsk`, `plan`, `default` — режимы Claude Code как есть.

Инструменты канала (`reply_to_user`, `send_file_to_user`) разрешены заранее.
`AskUserQuestion`, `EnterPlanMode` и `ExitPlanMode` запрещены — без TUI они
подвисают молча. `ExitPlanMode` ждёт одобрения плана, но его диалог в
headless-PTY не рисуется и в релей разрешений не уходит, поэтому ход зависал
навсегда и очередь сообщений оператора переставала разбираться. Вместо них
модель задаёт вопрос сообщением, а план излагает текстом.

## Файлы

- **Ты → Claude**: пришли фото или документ в топик (в вебе — drag&drop или
  скрепка). Файл ляжет в папку сессии (`INCOMING_DIR`, по умолчанию `incoming/`),
  а модель получит путь.
- **Claude → ты**: модель присылает файлы сама, инструментом
  `send_file_to_user`, и только по явной просьбе. Отдавать можно лишь то, что
  лежит внутри рабочей области сессии.

## Терминал `/bash`

`/bash` — постоянный терминал, работающий **мимо** Claude. Полезен, чтобы
посмотреть что-то самому, не тратя контекст модели.

| Где вызван | Где выполняется |
|------------|-----------------|
| в топике сессии | в той же песочнице, что и сессия: видит только её папки |
| в основном чате | **на хосте, без песочницы**, из твоего домашнего каталога |

Терминал живёт между вызовами: переменные и текущий каталог сохраняются.
`/bashin <текст>` досылает ввод в запущенную команду (например, ответ на
запрос пароля). Команда доступна только тем, кто в `ALLOWED_USER_IDS` —
модель ею пользоваться не может.

Если вывод команды не умещается в статус-сообщение, он приезжает файлом — не
нужно гадать, что отрезалось. Короткий вывод остаётся как прежде, без файла.

Вывод пишется в файл по мере поступления, а не собирается в памяти, поэтому в
него помещается всё: полный лог сборки, `pytest` на большом наборе (проверено на
200 тысячах строк). Две оговорки: Telegram не примет файл больше 50 МБ — такой
останется лежать в папке сессии; и место на диске никто за тебя не считает, так
что `yes` или `cat /dev/urandom`, забытые на десять минут, забьют раздел.

**Липкий режим** (`/term on`) делает топик терминалом: обычные сообщения
уходят в шелл (тот же, что у `/bash`), а не claude. Чтобы отправить
сообщение claude, начни его с `>` — префикс снимается. Экранирование `>>`
оставляет возможность послать в шелл строку, которая сама начинается с `>`
(например, перенаправление вывода `> file`). `/term off` выключает режим,
`/term` без аргументов показывает статус.

В основном чате включить липкий режим нельзя: там `/bash` идёт на хосте с
правами оператора без песочницы, и случайно отправленное сообщение
выполнилось бы на нём.

**Правка сообщения = перезапуск команды.** Если команда была отправлена через
`/bash` или в липком режиме, правка сообщения (редактирование в Telegram)
переисполняет команду и обновляет тот же статус-ответ. Ошибся в команде —
поправил текст, и в чате один чистый ответ вместо трёх попыток. Правка
постороннего сообщения игнорируется.

**Кнопки под выводом** — у каждого статус-сообщения есть inline-клавиатура:
- ⏹ **Прервать** — посылает Ctrl-C в терминал (прерывает убежавшую команду,
  не дожидаясь таймаута);
- ↻ **Повторить** — запускает последнюю команду этого терминала снова;
- 🕘 **История** — показывает меню последних команд (кнопками), тап по любой
  выполняет её. Замена «стрелке вверх», которой в чате нет.

## Модель и контекст

- `/model` без аргумента показывает кнопки выбора, с аргументом — ставит явно
  (`/model opus`, `/model claude-sonnet-5`). Работает на лету, сессия
  перезапускается с сохранением контекста.
- Модель по умолчанию для новых сессий — `DEFAULT_MODEL` в `.env`.
- `/stats` — сколько контекста занято, какая модель реально отвечает, аптайм.
- `/compact` — попросить Claude сжать контекст; `/clear` — начать с чистого
  листа (топик и папка остаются).
- `/usage` — расходы и лимиты плана.

## Изоляция сессий

Механика та же, что у `claude-box`: движок `bwrap` (по умолчанию), `off` или
microVM; что именно видно изнутри и почему — [`BOX.md`](BOX.md#что-видно-из-песочницы).
Оркестратор добавляет к этому три вещи.

**Движок по умолчанию** задаёт `SANDBOX` в `.env`, а рабочая область сессии —
это её собственная папка плюс папка проекта (и `SANDBOX_EXTRA_RW`, если задан).
Дом сессии персистентный: venv и кэши агента переживают перезапуск.

**Движок на сессию** выбирается при создании:

```
/new тесты --box off        # без изоляции: полный доступ к хосту
/new бэкенд /home/u/api     # как обычно, движок по умолчанию
```

Выбор живёт с сессией: продолжение и `/clear` поднимут её тем же движком. Сессия
с нестандартной изоляцией помечена в `/list` и в веб-списке. Доступные значения
— `off` и движок из `SANDBOX`; `vm` можно выбрать, только если он и указан в
`SANDBOX`: его обвязка настраивается один раз при старте оркестратора.

⚠️ **`--box off` отключает и защиту секретов.** Без песочницы процесс работает с
твоими правами: модель читает и файл секретов, и данные соседних сессий. Кошелёк
в такой сессии не подключается, а `/new` сразу отвечает предупреждением. Это
нормально для разовой задачи «поковыряться на хосте», но не для работы с чужим
кодом.

**Docker внутри сессии** — `SANDBOX_BWRAP_DOCKER=true` (только с `bwrap`): у
каждой сессии свой прокси над `docker.sock`, монтировать наружу она может только
свою папку проекта, снос системы и доступ к контейнерам соседей режется. Твой
личный докер при этом свободен.

## Профили — разные учётки Claude

Профиль — отдельная идентичность Claude Code: свои токены, скиллы, плагины и
транскрипты. Нужен, когда разные сессии должны работать под разными учётными
записями (рабочая и личная, свой аккаунт на каждого заказчика) — иначе все
сессии живут в одном профиле и делят авторизацию.

Профиль по умолчанию задаёт `CLAUDE_PROFILE` в `.env`, а сессия может выбрать
свой при создании:

```
/new бэкенд --profile work      # своя учётка
/new разовая --profile ""       # явно без профиля, общая учётка
```

Как и движок изоляции, выбор живёт с сессией: продолжение и `/clear` поднимут её
тем же профилем, а нестандартная учётка помечена в `/list` и в веб-списке. Имя
профиля — буквы, цифры, точка, дефис и подчёркивание (до 64 символов).

Каталоги профилей общие с `claude-box`
(`${CLAUDE_BOX_HOME:-~/.local/share/claude-box}/profiles/<имя>`): профиль,
созданный командой `claude-box init work`, доступен и боту, и наоборот. Создаётся
он сам при первом запуске — **первый вход под новым профилем попросит
залогиниться**, это ожидаемо: учётка новая.

Под `bwrap` профиль меняет именно учётку — приватный дом у сессии свой в любом
случае. Под `SANDBOX=agent-vm` профили **не работают**: гостевая VM держит креды
у себя и хостовый каталог конфигурации игнорирует, поэтому `--profile` там
отвечает отказом, а не делает вид, что сработал. Нужна отдельная учётка под VM —
создавай сессию с `--box bwrap`.

### Учётка запрещает dev-каналы

Учётка из Team-орга может запрещать каналы, которыми оркестратор доставляет
сообщения в сессию: Claude Code пишет «Channels are not enabled for your org».
Раньше это выглядело хуже всего, чем могло: сессия поднималась, числилась
готовой и молчала — сообщения уходили в никуда без единого признака.

Теперь оркестратор это замечает и сразу говорит: приходит заметка с причиной, а
сессия помечена «⌨️ без канала» в `/list` и в веб-списке. Сообщения при этом
**продолжают доходить** — они печатаются прямо в терминал сессии, и каждое
такое отмечено в бабле как «⌨️ через терминал».

Обход односторонний: он несёт твои сообщения модели. Ответы приходят как
обычно, а вот запросы разрешений, которые ходят каналом, до тебя не дойдут —
сессия в таком режиме рабочая, но урезанная. Починить по-настоящему можно двумя
способами: `/profile` с учёткой, где каналы разрешены, либо
`channelsEnabled: true` в managed settings орга.

## Секреты в чате

Кошелёк ([`WALLET.md`](WALLET.md)) при `SANDBOX=bwrap` включён по умолчанию и из
коробки разрешает `gh`, `git`, `ssh`, `scp` с кредами хоста. Оркестратор
добавляет к нему интерфейс:

- `/wallet` — посмотреть и править политику прямо из чата (значения скрыты);
- строка `🔐 wallet: …` в статус-бабле на каждое обращение — видно, что и когда
  модель запрашивала;
- кнопки подтверждения перед исполнением, если у секрета `confirm = true`;
- предупреждение оператору, когда политика разошлась с окружением живой сессии.

## Веб-интерфейс

Включается `ADAPTERS=web` (или `telegram,web`). Локальная страница на
`http://127.0.0.1:8180/?token=…`; URL с токеном печатается в лог при старте, а в
Telegram его выдаёт `/orchestrator_web`.

Умеет всё то же: список сессий и их создание, чат с историей (переживает
перезапуск), живой статус-бабл с теми же кнопками, карточки разрешений, файлы в
обе стороны, `/stats`, `/usage`, смену модели, `/compact`, `/clear` и панель
bash.

Наружу (не на `127.0.0.1`) выставляй только за reverse-proxy с TLS.

## Что лежит на диске

| Путь | Что это |
|------|---------|
| `SESSIONS_DIR` (по умолчанию `~/claude-orchestrator-sessions`) | всё про сессии |
| `SESSIONS_DIR/<имя>/` | папка сессии: `claude.log`, `.mcp.json`, `.claude/` (настройки и хук-диспетчер), `incoming/` |
| `SESSIONS_DIR/.sessions.json` | список сессий (имя, топик, модель, движок изоляции) |
| `SESSIONS_DIR/.history.json` | журнал сообщений — из него веб рисует историю после перезапуска |
| `SESSIONS_DIR/.live_bubbles.json` | снимок живых статус-баблов, чтобы они пережили перезапуск |
| `SESSIONS_DIR/.homes/<имя>/` | приватный `$HOME` сессии: venv, кэши агента, доступ к кошельку |
| `~/.config/claude-orchestrator/secrets.toml` | секреты и политика кошелька (`0600`) |
| `.env` в каталоге репозитория | настройки оркестратора |

Удалить сессию целиком — `/delete_session` в её топике (сама папка сессии
остаётся на диске; удаляй руками, если не нужна).

## Обслуживание

```bash
systemctl --user restart claude-orchestrator     # перезапуск
systemctl --user stop claude-orchestrator        # остановить
journalctl --user -u claude-orchestrator -f      # логи
git pull && ./install.sh && systemctl --user restart claude-orchestrator   # обновление
./install.sh --uninstall                         # снять сервис (репозиторий и .env остаются)
```

Перезапустить можно и из чата — `/orchestrator_restart`; сессии при этом
останавливаются, но записи и контекст сохраняются, продолжатся с первого
сообщения.

## Если что-то не работает

**Бот молчит на любые сообщения.** Пустой или неверный `ALLOWED_USER_IDS` —
это единственное поведение при незаполненном белом списке. Проверь свой ID и
перезапусти сервис.

**Бот не создаёт топики.** В группе не включены Topics, либо бот не админ, либо
у него нет права «Управление темами».

**Сессия не поднимается, в ответе «Claude не поднял channel-сервер».** Смотри
`claude.log` в папке сессии (или `/log`). Частая причина — Claude Code не
залогинен или обновился и изменил протокол channels (research preview). Проверь,
что `claude` в терминале запускается сам и без вопросов.

**Сессия под microVM (`agent-vm`) долго стартует.** Первый запуск тянет образ —
это минуты. Прогрей заранее: `agent-vm setup`.

**Модель не видит установленных программ / venv.** Так и задумано: `$HOME`
изолирован. Ставь окружение внутрь папки проекта.

**Модель говорит, что переменной с секретом нет.** Проверь `wallet doctor` в
сессии: он сравнивает политику с реальным окружением и подсказывает, что
случилось (например, `source .env` затёр значение пустым).

**Кошелёк не включился.** Он работает только с `SANDBOX=bwrap`; при другой
изоляции в логе будет явный WARNING. Сессии, созданные с `--box off`, тоже без
кошелька — это ожидаемо.

**`/bash` в топике отвечает отказом.** Под `agent-vm` отдельный терминал
изолировать нечем (одна VM на каталог) — используй `bwrap`.

**`/new` отвечает про лимит.** Достигнут `MAX_INSTANCES` запущенных сессий (по
умолчанию 5). Останови ненужную (`/close_session` — запись и топик останутся,
слот освободится) или подними лимит в `.env`. Остановленные сессии в лимит не
входят, так что после рестарта оркестратора он не срабатывает на пустом месте.

**`/new` отвечает про память.** Машине после старта осталось бы меньше
`MIN_FREE_RAM_MB`. Останови ненужную сессию или снизь порог в `.env`
(`0` выключает проверку).

**Нас несколько.** Все, кто перечислен в `ALLOWED_USER_IDS`, работают с одними и
теми же сессиями в общей группе: любой может написать в топик и ответить на
запрос разрешения. Отдельных пространств на пользователя нет.

**Обновился — появились новые настройки.** `.env` при обновлении не
перезаписывается. Загляни в `.env.example` (он обновляется вместе с кодом) или в
[справочник настроек](CONFIG.md) — новые параметры имеют разумные значения по
умолчанию, доставать их из примера нужно, только если хочешь изменить.

**Порты заняты / сессия не стартует после падения.** Проверь, что не запущено
два оркестратора: `systemctl --user status claude-orchestrator` и
`pgrep -af "python -m orchestrator"`.
